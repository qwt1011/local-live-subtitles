# 扩展端（M4/M5）安装与验收

## 装什么

1. 启动本地流式服务（**必须用 `-m`**，`app/server.py` 里有相对导入）：

   ```powershell
   # 只出原文
   C:\text\.venv\Scripts\python.exe -u -m app.server --engine sensevoice --model sensevoice-2024

   # 原文 + 中文（推荐）
   C:\text\.venv\Scripts\python.exe -u -m app.server --engine sensevoice --model sensevoice-2024 --translate
   ```

   看到 `流式字幕服务已启动：ws://127.0.0.1:8766` 才算好。

2. Chrome/Edge 打开 `chrome://extensions` → 打开「开发者模式」→「加载已解压的扩展程序」→
   选这个 `extension` 目录。

3. 打开任意 YouTube 视频 → 点扩展图标 → 选语言（日语/英语）→「开始捕获当前标签页」。

## ⚠ 改了扩展代码之后，怎么让它真的生效

**这是最容易白费功夫的地方。** 扩展是「已解压」方式加载的，Chrome 不会自动重读文件。

代码改完后必须按顺序做这三步，缺一步就会觉得"改了但没反应"：

| 步骤 | 操作 | 不做会怎样 |
|---|---|---|
| 1 | `chrome://extensions` → 本扩展 → 点**刷新图标 ↻** | service worker、popup、offscreen 都还是旧代码 |
| 2 | **关掉再重新打开 popup** | popup 是独立页面，不重开会一直跑旧 JS |
| 3 | **刷新 YouTube 标签页**（F5） | content script 只在页面加载时注入，旧页面里还是旧脚本 |

**怎么确认加载的是新版本**：在 YouTube 页面按 F12 → Console，刷新后应该看到：

```
[本地字幕] content script 已就绪（v0.2.0）
```

看到这行说明第 3 步生效了。收到字幕时还会打印 `[本地字幕] 定稿: …` 和 `[本地字幕] 译文: …`。

**确认版本号**：`chrome://extensions` 的扩展卡片上直接写着版本。
现在应该是 **0.2.0**；如果还是 `0.1.0`，说明第 1 步没成功。

**排查采集/连接问题**：`chrome://extensions` → 本扩展卡片 → 「检查视图」里会有
`offscreen.html`，点进去看它的 Console——PCM 采集和 WebSocket 都在那里。

## 自动化测试能覆盖什么

不需要浏览器就能验证的部分（改动后请先跑这两条）：

```powershell
node tests\test_extension_logic.js   # 24 项：PCM 分帧、revision 单调性、全屏挂载点、显示模式
node tests\test_ws_protocol.js       # 9 项：扩展的帧格式与服务端协议是否对得上（需服务在跑）
```

这两个测试是刻意做的：**"PCM 掉了一帧""revision 回跳一次""全屏挂载点选错"在浏览器里
都只表现为「字幕偶尔怪一下」，几乎无法复现**；在这里是确定的失败。
（写这套测试时它确实抓到了一个错误——虽然那次错的是测试自己的算术。）

## 只能靠真机验收的清单

下面这些必须开浏览器，逐条对照 `DEVELOPMENT.md` 第 9 节的验收标准。

| # | 检查项 | 期望 | 之前的状况 |
|---|---|---|---|
| 1 | 捕获当前标签页音频 | 字幕出现，且**标签页原声仍然可听** | 曾出现听不到声音 |
| 2 | **全屏下字幕可见** | 按 F 进全屏，字幕仍在 | **原来会完全消失**（挂在 `documentElement` 上） |
| 3 | 字幕不遮挡控件 | 进度条、播放按钮可正常点击 | 原来整个覆盖层都吃点击 |
| 4 | 草稿 → 定稿不闪烁 | 句子说完后文字原地定住，只变样式不变位置 | 原来整体替换文本，会跳 |
| 5 | **译文稍后原地补上** | 中文在原句定稿后约 0.7–0.9 秒出现，不闪烁 | 原来没有翻译 |
| 6 | 字幕不回跳 | 不会出现后一句被前一句覆盖 | 原来无序号，慢块后到会回退 |
| 7 | 拖动位置、滚轮改字号 | 松手后位置被记住 | 原来刷新就丢 |
| 8 | **刷新页面后设置保留** | 模式、字号、位置都不变 | **原来模式会回落到"双语"** |
| 9 | 三种显示模式 | 仅原文 / 仅中文 / 双语 切换立即生效 | — |
| 10 | popup 显示连接状态 | 显示引擎名和最近一条延迟，并标明草稿/定稿 | 原来只有一个笼统的"已连接" |
| 11 | 关掉服务后的表现 | popup 显示未连接，不静默卡死 | 原来会静默无反应 |

## 采集层的协议约定（改动时别踩）

- 格式：**16 kHz / 单声道 / s16le 裸 PCM**，由 `AudioContext({sampleRate:16000})` 重采样，
  不是手写重采样。
- 分帧：100 ms 一帧（1600 样点），见 `shared.js` 的 `FRAME_SAMPLES`。
- 客户端**不做任何分段决策**：句子切在哪完全由服务端 VAD 决定
  （ARCHITECTURE_REVIEW.md 第 4 节不变式 1）。改这里之前先读那一条。
- `AudioWorkletProcessor.process()` 返回后输入缓冲区会被复用，`postMessage` 前必须 `slice()`。

## 已知限制

- 只支持 YouTube（`content_scripts.matches` 与 `host_permissions` 都写死了 youtube.com）。
- 只支持 16 kHz 音频链路；如果将来要在扩展里直接做别的采样率，改 `shared.js` 的常量并同步服务端。
- **翻译已接入（M5）**：服务端开着 `--translate` 时，译文会作为同一个 `segment_id` 的
  更高 `revision` 到达，渲染端原地补上（`is_final` 为真但带 `translation` 字段）。
  实测中文出现在说完后 0.67–0.88 秒。翻译质量是 0.5B 模型的水平：够看懂大意，不保证精致。
  服务端没开 `--translate` 时只显示原文，界面不会报错。
